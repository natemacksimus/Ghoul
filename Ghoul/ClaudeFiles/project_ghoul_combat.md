PlayerAttack was redesigned (2026-06-30) into a traveling directional hitbox with reflecting knockback. Builds on [[project-ghoul-multiplayer]] client-authority model.

**Behaviour:** On attack press, a square hitbox spawns at the player's collider center and slides in the held direction (or `lastDirInput` if none held) for `hitboxDistance` world units at `hitboxSpeed`. On contact it damages + knocks the target back **along the hitbox travel direction**. The knocked-back target reflects off surfaces (`Vector2.Reflect`, angle out = angle in) up to `knockbackBounces` times, then recovers. Each bounce multiplies speed by `knockbackBounciness` (0..1, `[Range]` on PlayerAttack; 1 = no energy loss, threaded through the RPC chain into `ApplyDirectionalKnockback`).

**Key design decisions (the non-obvious "why"):**
- Did NOT change the shared `IDamageable.Knockback(Vector2,float,int)` interface — it's still used by the legacy animation-driven `Damage.cs` / `Item.cs` / `InteractableObjects.cs`. Instead added a PARALLEL directional path so those aren't disturbed. `AttackHitboxLogic` calls the concrete `CharacterStats.KnockbackDirectional(dir, power, time, bounces)` directly (it already resolves `CharacterStats` via GetComponentInParent).
- Networking mirrors the existing knockback exactly: `CharacterStats.KnockbackDirectional` → ServerRpc(RequireOwnership=false) → targeted ClientRpc to `OwnerClientId` → `EntityController.ApplyDirectionalKnockback` runs on the victim's OWNING client (client-authority), so bounce physics simulate on the owner and sync to others via ClientNetworkTransform.
- Reflection normal comes from `Controller2D.collisions`: `slopeNormal` for slopes, else derived from the `below/above/left/right` flags (up/down/right/left). Read at the START of the next FixedUpdate (collisions reflect the previous frame's `Move`).
- `EntityController` gained a directional-knockback state (`directionalKnockback`, `knockbackVelocity`, `knockbackBouncesRemaining`) running IN PARALLEL to legacy `HandleKnockback` — `FixedUpdate` branches on `directionalKnockback`. Velocity is units/sec (Move multiplies by dt), same convention as jump/speed.
- `PlayerController` suppresses gravity + terminal-velocity clamp (in `CalculateMoveAmount`) and the floor/ceiling y-zeroing (in `Move`) while `directionalKnockback` is active, so the flight is a straight line between bounces and reflection stays clean. `disableInput` (set by ApplyDirectionalKnockback) already skips x-smoothing.
- Attack now fires IMMEDIATELY on press (`PlayerController.UseItem` → `playerAttack.Attack(dir)`); removed the old "wait for a direction" `pendingAttack`/`FirePendingAttack`/`IsAttackPending` flow.

**Files:** `PlayerAttack.cs` (rewrite), `AttackHitboxLogic.cs` (rewrite), `EntityController.cs` (+directional knockback), `CharacterStats.cs` (+KnockbackDirectional RPC chain), `PlayerController.cs` (fire-on-press + knockback guards). Player.prefab PlayerAttack fields updated (hitboxDistance/Speed/SizeScale, knockbackPower/Time/Bounces); old attackDuration/attackKnockback(Vector2)/attackKnockbackTime removed.

**2026-09-09 rewrite — folded into rollback determinism.** Playtesting [[project-ghoul-rollback]] surfaced a hard desync: `PlayerAttack.Attack()` was gated `if (!IsOwner) return;`, but `RollbackSession` simulates BOTH players locally on BOTH peers every tick. So only the attacking player's own machine ever spawned the hitbox, ran its `OnTriggerEnter2D`, and called `InflictDamage`/`KnockbackDirectional` — the defending peer's local copy of the target never took the hit at all. Health and (via directional knockback) position permanently split the instant anyone landed an attack. The hitbox was also driven by `StartCoroutine`+`yield return null` (real render-frame cadence, not the fixed tick) and wasn't `ISnapshotable`, so even the attacker's own rollback resimulation could silently drop it.

Fixed by making the swing part of the deterministic simulation instead of a side effect of ownership:
- `AttackHitboxLogic.cs` **deleted**. `PlayerAttack` now implements `ISnapshotable` directly and owns all swing state (`cooldownTimer`, `attackActive`, `attackDirection`, `attackTraveled`, `hasHitTarget`) — auto-registered by `RollbackSetup.CollectFromPlayer`'s `GetComponents<ISnapshotable>()` scan, no wiring needed.
- No more `IsOwner` gate, no more coroutine. `Attack()` just arms the swing; `PlayerAttack.Tick()` advances it by `hitboxSpeed * Time.fixedDeltaTime` and is called every tick from `PlayerController.RunFixedStep()` — which already runs identically on both peers via `SimulateFrame`, live or during rollback resimulation.
- Hit detection is a manual `Bounds.Intersects` check against the other player's `BoxCollider2D.bounds` (resolved once via `FindObjectsByType<CharacterStats>`, cached — exactly one other player exists in this 2-player co-op model) instead of a Physics2D trigger callback. Avoids depending on Unity's async trigger-dispatch timing relative to the manual resimulation loop, and sidesteps the live-Physics2D-world determinism risk entirely for this hit check.
- `CharacterStats.KnockbackDirectional` gained the same rollback-active local-apply branch `InflictDamage` already had — it no longer routes through the ServerRpc→ClientRpc chain while rollback owns the session, since an RPC lands out-of-band from the fixed tick and would be silently discarded on the next rollback resimulation.
- The red square hitbox visual is now a single persistent `GameObject` (position/size/active mirrored from the simulated state each `Tick()`), so it renders identically on both peers instead of only the attacker's screen.

Verified: clean compile via Unity MCP, no console errors/warnings.

**2026-09-30 — knockback is now an impulse with exponential falloff.** Previously `HandleDirectionalKnockback` held `knockbackVelocity` constant for the whole `knockbackTime` and then stopped dead, which felt like a steady push. Now the hit sets the full velocity instantly (the first step moves at full speed). After each step, `knockbackVelocity *= Mathf.Exp(-knockbackDecayRate * Time.deltaTime)`, and the knockback ends once speed drops below `knockbackStopSpeed`; `knockbackTime` is only a safety cap. Decay rate (default 8/s) and stop speed (default 1.5) live on the **receiver** (`EntityController`, like drag), so the hit/RPC chain didn't change. They're config, not snapshotted state, and deterministic because both peers use the same prefab. Total push distance ≈ `knockbackPower / knockbackDecayRate`. The Player prefab was retuned to power 20 and time 0.4 to keep roughly the old 2.5-unit distance (previously 10 × 0.25 at constant speed), now front-loaded. Bounces still multiply speed by `knockbackBounciness`, and decay keeps running after a bounce. The legacy `ApplyKnockback`/`HandleKnockback` path (animation-driven `Damage.cs`) is unchanged.

**2026-09-30 — knockback holds its trajectory.** A knocked-back target now flies in a straight line (the gravity suppression from before, and decay only scales speed) until the knockback decays out/times out or the target **lands**: `collisions.below && knockbackVelocity.y < 0` ends it (ground no longer bounces). Walls and ceilings still reflect, up to `knockbackBounces`. A target already grounded and knocked sideways has `y == 0`, so it slides rather than stopping; a grounded target hit at a downward angle stops immediately. `PlayerController.Move()` now skips the animation-driven `continueMoveX` / `ZeroMoveX` overrides while `directionalKnockback` is active; previously they could replace or zero the knockback's X mid-flight.

**2026-09-30 retune:** knockback decay felt too strong ("the horizontal decay is way too large"), so `knockbackDecayRate` went 8 → **3** (script default and Player prefab). The attack's `knockbackTime` cap went 0.4 → **1.0** so the cap doesn't cut off a still-fast knockback. With power 20 the push now lasts about 0.85 s and travels about 6 units (vs about 2.5 before). One rate applies to both axes on purpose; a separate horizontal rate would bend diagonal knockbacks.

**2026-09-30 — gravity applies during knockback (replaces the straight-line behavior above).** Knockback velocity is now two parts: `knockbackVelocity`, the impulse (decays each step), and `knockbackFallVelocity`, gravity (builds up normally, never decayed). `moveAmount = impulse + (0, fall)`, so the flight arcs. `PlayerController.CalculateMoveAmount` calls `EntityController.ApplyKnockbackGravity(gravityStep, fallAmountMax)` during knockback instead of skipping gravity. It uses the same gravity, fall multiplier and terminal velocity as a normal jump (prefab gravity −3/step ≈ −180 u/s², so arcs drop quickly). `knockbackAirborne` records whether the target left the ground. **Ending:** landing after being airborne; being knocked down into the ground it's standing on; the impulse decaying below `knockbackStopSpeed` (moveAmount keeps the fall speed, so normal gravity continues seamlessly); or the time cap. While still grounded from a sideways or upward hit, the fall velocity resets to 0 each step (the ground supports it), so the target slides. **Bounces:** walls/ceilings reflect the *combined* velocity, which becomes the new impulse, and the fall velocity resets. Both new fields are snapshotted (`EntityController.SaveState/LoadState`, after `knockbackBounciness`). Non-player EntityControllers have no gravity, so their knockback stays straight.

**2026-09-30 — floors bounce too; reflection uses real surface normals (replaces "landing ends it" above).** A knocked-back target bounces off walls, floors and ceilings while bounces remain; the next impact after that ends the knockback, as does the impulse decaying out or the time cap.
- **Impact** = moving into a touched surface (`Dot(incoming, normal) < 0`). `incoming` is `moveAmount` at the start of the step: the exact velocity last step's `Move()` used (impulse + fall + gravity). It's not the decayed impulse, whose direction differs once gravity is involved.
- **Real normals:** `Controller2D.CollisionInfo` now records `horizontalHitNormal` (wall) and `verticalHitNormal` (floor/slope/ceiling) from the actual raycast hit. They're set in HorizontalCollisions, VerticalCollisions, ClimbSlope, the climbing-slope re-check and DescendSlope, cleared in `Reset()`, and **snapshotted** in `EntityController.SaveState/LoadState` (after `fallingThroughPlatform`). The old `GetCollisionNormal()` guessed axis normals from flags, which was wrong on slopes and gave a fake 45° normal at corners. It was removed.
- **Reflection:** `Vector2.Reflect(incoming, n)` (mirror: tangential part kept, normal part flipped). A corner (floor/ceiling plus wall in the same step) reflects across both, giving exactly −v, and counts as one bounce. Bounciness scales speed only. Verified numerically in-editor: flat floor, wall, ceiling, 30° slope and bounciness 0.6 all give incidence = reflection (diff ≤ 1e-5°); the corner gives exactly −v.
- **Resting contact isn't an impact:** `supported = below && !knockbackAirborne && impulse.y >= 0` (still on the ground after a sideways/upward hit). The fall velocity resets, gravity's press into the floor is dropped from `incoming`, and the floor isn't treated as a hit, so the target slides. A wall hit while sliding still bounces.
- After a bounce the reflected velocity is the new impulse (it keeps decaying) and gravity builds again from 0, so the path after leaving a surface curves under gravity, just as the path into it did. The mirror symmetry holds at the moment of contact.
